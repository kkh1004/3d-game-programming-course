새 컴퓨터에서 작업 이어가기

3d-game-programming-course 저장소를 다른 PC에서 이어받는 절차

작성 2026-08-26 · 대상 Windows · 저장소 kkh1004/3d-game-programming-course

이 문서만 보고 처음부터 끝까지 할 수 있게 썼습니다. 1~4번은 그 컴퓨터에서 한 번만 하면 되고, 그 뒤로는 5번만 반복합니다.

먼저 알아둘 것 이 프로젝트는 빌드 도구가 없는 단일 HTML 파일 4개로 되어 있습니다. Node.js·npm 설치가 필요 없습니다. Git과 브라우저만 있으면 됩니다.

1Git 설치 확인

명령 프롬프트(Win + R → cmd → Enter)를 열고 입력합니다.

git --version

git version 2.xx.x 처럼 나오면 설치되어 있습니다. "명령을 찾을 수 없습니다"가 나오면 아래에서 설치하고 설치 후 명령 프롬프트를 새로 엽니다.

https://git-scm.com/download/win

2저장소 내려받기

작업 폴더를 정하고(예: D:\클로드프로젝트) 그 안에 내려받습니다. 아래 두 줄을 그대로 붙여넣으면 됩니다.

mkdir D:\클로드프로젝트 cd /d D:\클로드프로젝트 git clone https://github.com/kkh1004/3d-game-programming-course.git

끝나면 D:\클로드프로젝트\3d-game-programming-course 폴더가 생깁니다. index.html ~ index4.html, apps-script, docs 폴더가 보이면 정상입니다.

3커밋에 쓸 이름·이메일 설정

이 단계는 건너뛰면 안 됩니다 Git의 이름·이메일은 저장소 내용이 아니라 그 컴퓨터의 설정입니다. 내려받아도 따라오지 않으므로 새 PC에서 다시 해야 합니다. 안 하면 커밋 자체가 되지 않습니다.

기존 커밋과 같은 값을 씁니다. 저장소 폴더 안에서 실행하세요.

cd /d D:\클로드프로젝트\3d-game-programming-course git config user.name "kkh1004" git config user.email "beatkkh1004@gmail.com"

--global 없이 실행하므로 이 저장소에만 적용됩니다. 다른 작업에 영향을 주지 않습니다.

4GitHub 로그인 — 그 PC에서 한 번만

수정한 내용을 GitHub에 올리려면(push) 로그인이 필요합니다. 이 로그인은 사람이 직접 한 번 해야 합니다. Claude는 로그인 창을 띄울 수 없습니다. 한 번 해두면 그 뒤로는 Claude가 push까지 알아서 처리합니다.

방법 A · GitHub Desktop (가장 쉬움)

  1. https://desktop.github.com 에서 설치
  2. 실행 → Sign in to GitHub.com → kkh1004 계정으로 로그인
  3. File → Add local repository → 경로에 D:\클로드프로젝트\3d-game-programming-course 선택
  4. 우측 상단 Push origin 을 한 번 눌러 봅니다

방법 B · 명령 프롬프트

cd /d D:\클로드프로젝트\3d-game-programming-course git push origin master

로그인 창이나 브라우저 탭이 열리면 kkh1004 로 로그인·승인합니다. 올릴 것이 없으면 Everything up-to-date 가 나오는데, 그래도 로그인은 저장됩니다.

제대로 저장됐는지 확인

cmdkey /list | findstr github

결과에 git:https://github.com 이 반드시 있어야 합니다.

자주 겪는 함정 GitHub Desktop의 로그인 정보(GitHub - https://api.github.com/...)와 Git 명령줄의 로그인 정보(git:https://github.com)는 서로 별개입니다. Desktop만 로그인돼 있으면 명령줄 push는 계속 막히고, Claude도 올릴 수 없습니다. 위 확인 명령에 git:https://github.com 이 안 보이면 방법 B를 한 번 실행하세요.

5Claude Code로 작업 시작

저장소 폴더에서 Claude Code를 열고 이렇게 말하면 됩니다.

이어서 작업하자

Claude가 저장소에 들어있는 두 문서를 읽고 현재 상황을 파악한 뒤 시작합니다. 코드를 처음부터 다시 분석하지 않습니다.

문서담고 있는 내용
CLAUDE.md코드가 어떻게 생겼는지 (세션마다 자동으로 읽힘)
docs/00-이어서-작업하기.md작업이 어디까지 왔는지 · 남은 항목 · 주의사항
docs/01~04앱 4개의 상세 구조

특정 앱을 고치고 싶으면 앱 이름으로 말하면 됩니다. "시간표 생성기 ○○ 고쳐줘", "프로젝트팀 관리에서 ○○ 바꿔줘" 처럼요.

6앱 4개 — 어느 파일이 무엇인지

파일앱서버
index.html공지 메일 작성기Gmail API
index2.html과목 소개페이지없음
index3.html프로젝트팀 관리 시스템apps-script/Code.gs
index4.html시간표 생성기apps-script/Timetable.gs

이름만 비슷하고 서로 아무 코드도 공유하지 않는 별개의 앱입니다. 파일 이름과 위치는 바꾸지 마세요. GitHub Pages 주소가 깨집니다.

7반드시 기억할 두 가지

① 학생 데이터는 GitHub에 없습니다

데이터사는 곳백업
명단 · 팀 배정 · 평가 점수구글 시트앱의 팀 배정 탭 → 내보내기 (엑셀)
학생 평가용 비밀번호구글 시트 (해시)복구 불가 — 잊으면 교수가 초기화

코드를 되돌려도 데이터는 돌아오지 않습니다. 팀 배정이나 평가를 건드리는 작업 전에는 엑셀 내보내기를 먼저 하세요.

② .gs 파일은 GitHub에 올려도 반영되지 않습니다

Code.gs · Timetable.gs 는 구글 서버에서 도는 코드입니다. 고쳤으면 script.google.com 에 직접 붙여넣고 재배포해야 합니다.

  1. script.google.com 에서 해당 프로젝트 열기 (팀 관리용과 시간표용은 별개 프로젝트)
  2. 편집기에서 Ctrl+A → Ctrl+V → Ctrl+S
  3. 배포 → 배포 관리 → 연필(편집) → 버전: 새 버전 → 배포
'새 배포'를 누르지 마세요 배포 관리 → 편집으로 해야 주소(URL)가 그대로 유지됩니다. 새 배포를 누르면 주소가 새로 발급되어 앱이 서버를 찾지 못합니다.

  • git config user.email 이 beatkkh1004@gmail.com 을 출력한다
