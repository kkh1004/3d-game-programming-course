## 무엇을 하는 앱인가

학생 명단을 엑셀로 올려서 **프로젝트 팀을 짜고, 팀원끼리 상호평가를 받고, 결과를 집계**하는 시스템.
교수와 학생이 **같은 URL을 공유**하며, 데이터는 구글 시트 한 칸에 JSON으로 저장되어 실시간 동기화된다.

## 🔑 가장 중요한 원칙 — 평가 점수는 절대 공개 상태에 넣지 않는다

`doGet` / `doPost` 는 반드시 **`publicState()` 를 거친 데이터만** 내려준다.

```js
function publicState(state) {
  return {
    roster, teamsByGrade, assignedMap, evalEnabled,
    submittedIds,   // 제출한 학번 목록 (점수 없음)
    authedIds       // 비밀번호를 만든 학번 목록
  };
}
```

`evaluations`(누가 누구에게 몇 점)와 `studentAuth`(비밀번호 해시)는 여기에 **들어가면 안 된다.**

> 예전에는 `state` 를 통째로 내려주고 있었다. 그래서 API 주소만 알면, 또는 F12만 누르면
> 전교생의 평가 점수를 볼 수 있었다. "결과" 탭의 교수 비밀번호는 화면만 가리는 장식이었다.
> 점수는 이제 본인이 `getMyEvaluation`, 교수가 `getResults` 로 각자의 비밀번호를 내고 받아간다.

새 기능을 넣을 때 **점수를 공개 상태에 얹고 싶어지면 그 설계가 틀린 것이다.**

## 탭 4개

| 탭 | `data-tab` | 역할 |
|---|---|---|
| 명단 업로드 | `upload` | 엑셀 파일 → 학생 명단 파싱·병합 |
| 팀 배정 | `team` | 드래그앤드롭 배치 · 반(a/b/c) 필터 · 다른 학년 데려오기 |
| 상호평가 | `eval` | 학번+이름 조회 → **본인 비밀번호 확인** → 팀원 평가 |
| 결과 | `results` | 교수 비밀번호로 결과 수신 · 제출 현황 · 평가 초기화 |

## 핵심 상수

```js
var ROLES = ['기획', '아트', '개발'];      // 팀 내 역할 슬롯
var INDIVIDUAL_GRADES = ['2', '3'];        // 개인 프로젝트로 취급하는 학년
var SECTION_GRADES = ['1'];                // 반(a/b/c)을 쓰는 학년 — 1학년만
var SECTIONS = ['a', 'b', 'c'];
var TEAMS_PER_SECTION = 10;                // 1~10팀=a반, 11~20팀=b반, 21~30팀=c반
var STORAGE_KEY = 'teamProjectGenState_v1';
var DEFAULT_PASSWORD = '1004';
var POLL_INTERVAL_MS = 5000;
var HIDDEN_POLL_FACTOR = 4;                // 탭이 백그라운드면 4배 느리게
```

**`SECTION_GRADES` / `SECTIONS` / `TEAMS_PER_SECTION` 은 `index3.html` 과 `Code.gs` 양쪽에 같은 값으로 있다.**
한쪽만 고치면 화면과 서버의 반 계산이 어긋난다.

## 반(수업반) — 1학년만

1학년은 반별로 팀이 편성된다. 팀마다 `section` 필드(`'a'|'b'|'c'`)를 갖는다.

### ⚠️ 반은 팀 번호 구간으로 정해진다 — 이게 핵심 불변식

```
a반 = t1~t10     b반 = t11~t20     c반 = t21~t30
```

`sectionBase(section)` = `SECTIONS.indexOf(section) * TEAMS_PER_SECTION`

이 규칙이 있어야 **반별 팀 개수를 세고, 새 팀을 어느 번호로 만들지** 알 수 있다.
그래서 **팀의 반만 따로 바꾸는 기능은 없다.** (`setTeamSection` 은 만들었다가 이 불변식과
충돌해서 제거했다. 번호와 반이 어긋나면 개수 계산이 깨진다.)

반을 옮기려면 **한쪽 반 개수를 줄이고 다른 쪽을 늘린다.**

- 팀 배정 탭에 **반 필터 칩**이 1학년에서만 나타난다 (`teamSectionFilter`)
- 팀 카드에는 반이 **읽기 전용 태그**(`.team-section-tag`)로 표시된다
- `teamSection(team)` — 값이 없으면 팀 번호로 계산해서 돌려준다. 서버에 닿지 못해도 화면이 비지 않게 하는 폴백
- 2·3학년은 반 없이 팀 번호만 쓴다. 학년을 바꾸면 반 필터는 '전체'로 되돌아간다

### 팀 번호는 반마다 1팀부터 다시 센다

내부 id 와 서버에 저장된 `name` 은 절대 번호 그대로다 (`t11` / `"11팀"`).
**화면에만** 반 기준으로 다시 세어 보여준다 — b반 `t11` 은 `1팀`.

| 함수 | 결과 | 쓰는 곳 |
|---|---|---|
| `absoluteSlotLabel(teamId)` | `11팀` | 저장되는 `name`, 옛 데이터에서 팀명 물려받을지 판단 |
| `slotLabel(teamId, grade)` | `1팀` (1학년) / `11팀` (2·3학년) | 팀 카드, 내보내기, 토스트 |
| `teamFullName(team, grade)` | `b반 1팀 (팀명)` | 평가 화면처럼 학년 전체를 놓고 가리킬 때 |

⚠️ `teamTitle()` 의 레거시 비교는 **반드시 `absoluteSlotLabel` 과** 해야 한다.
`slotLabel` 과 비교하면 `name:"11팀"` 인 팀이 "11팀"을 사용자 지정 팀명으로 오인한다.

반마다 1팀이 하나씩 생기므로 `1팀` 이 세 개 존재한다. 팀 카드에는 반 태그가 붙어 구분되고,
학년 전체를 가리킬 때는 `teamFullName` 이 반을 앞에 붙인다.

## 팀 개수 — 학년 단위 vs 반 단위

| 보고 있는 화면 | 팀 개수 입력칸 | 액션 | 상한 |
|---|---|---|---|
| 2·3학년 | `팀 개수` | `setTeamCount` | 30 |
| 1학년 + 반 선택(a/b/c) | `a반 팀 개수` | `setSectionTeamCount` | 10 |
| **1학년 + 전체 반** | **숨김** — 반별 현황만 표시 | 없음 | — |

전체 반 보기에서는 어느 반을 뜻하는지 알 수 없으므로 입력칸을 숨기고
`a반 10팀 · b반 10팀 · c반 10팀 / 총 30팀` 형태의 요약(`sectionCountSummary`)만 보여준다.

`setTeamCount` 는 **1학년에 대해 `'use section team count'` 오류로 거부한다.**
학년 단위로 개수를 바꾸면 반 구간이 뒤섞이기 때문이다.

반 개수를 줄이면 **그 반의 뒤쪽 팀부터** 사라지고 거기 배정됐던 학생만 미배정으로 돌아간다.
다른 반의 팀은 건드리지 않는다.

### 기존 데이터 이관 — `migrateTeamSections` / `migrateSectionCounts`

반 필드가 생기기 전에는 **팀 번호 범위로 반을 구분**해서 쓰고 있었다.
`Code.gs` 의 `readStore()` 가 매번 두 함수를 부른다.

- `migrateTeamSections` — `section` 이 없는 1학년 팀에 번호 기준 값을 채운다
- `migrateSectionCounts` — `teamCountBySection` 이 없으면 반별 실제 팀 수로 채우고, `teamCount` 를 합계로 맞춘다

**팀 배정 내용(`roles`)은 건드리지 않고 필드만 추가하므로 배정된 학생은 그대로 남는다.**
여러 번 실행해도 안전하다. (실제 운영 데이터는 30팀 → a/b/c 각 10팀으로 이관됨을 확인했다)

## 학년을 넘어 팀 배정하기

2·3학년 학생이 1학년 팀에 들어가는 경우가 있다.

- **명단(`roster`)의 `grade` 는 바뀌지 않는다.** 원 소속이 보존되고 되돌리기 쉽다
- 배정 위치는 `assignedMap[sid].grade` 에 기록된다 (= 팀이 속한 학년)
- 미배정 풀의 **"다른 학년 학생도 보기"**(`showOtherGradesChk`)를 켜면 다른 학년 학생을 끌어올 수 있다
- 다른 학년 학생의 칩에는 원 소속이 표시되고 `.is-other-grade` 로 색이 달라진다

### ⚠️ `removeStudentFromAllSlots` 는 학년을 가리지 않는다

예전에는 넘겨받은 학년의 보드만 훑었다. 학년 이동이 생기면서 **원래 학년의 팀 명단에 학번이 남는
유령 배정** 버그가 드러났다. 그래서 이제 모든 학년을 훑고, `grade` 파라미터도 없앴다.

`index3.html` 과 `Code.gs` 양쪽에 같은 이름·같은 규칙으로 있다. **한쪽만 고치지 말 것.**

## 학생 본인 확인 (평가용 비밀번호)

학번과 이름은 같은 팀원이면 다 아는 정보다. 그것만으로는 남이 내 평가를 열어보거나 내 이름으로
제출할 수 있었다. (예전 `submitEvaluation` 에는 본인 확인이 **아예 없었다**)

**흐름**: 학번+이름 조회 → 비밀번호(최초면 생성, 이후 확인) → 평가 화면

- 최초 1회 `setStudentPassword` — 학번+이름이 명단과 일치할 때만, 4자 이상, 이미 있으면 거부
- 저장은 **학번마다 다른 salt + SHA-256 해시**. 시트를 열어봐도 (교수 포함) 비밀번호를 알 수 없다
- 재진입은 `getMyEvaluation` — 비밀번호를 확인하고 **본인이 낸 점수만** 내려준다
- `submitEvaluation` 도 비밀번호 필수
- 비밀번호는 화면을 나가거나 제출하면 `clearEvalSession()` 으로 메모리에서 지운다
- 잊어버렸을 때는 교수가 초기화해 준다 (아래 "개인별 초기화" 참조 — 점수를 남길지 말지 두 갈래)

`uiBusy()` 에 `evalPwView` 가 포함되어 있다. 폴링이 비밀번호 입력 중인 화면을 갈아치우면 안 된다.

### ⚠️ 비밀번호 제도 이전에 제출한 학생

비밀번호가 생기기 전에 이미 제출한 학생이 있다. (도입 시점 실제 데이터: 제출 9명 / 비밀번호 2명)
이 학생들은 `studentAuth` 가 없으므로 다시 들어오면 **비밀번호 생성** 화면을 만난다.

그래서 `setStudentPassword` 성공 직후에 **곧바로 `getMyEvaluation` 으로 본인 제출분을 받아와**
채워 준다. 이걸 빼면 이미 낸 점수가 안 보여서 처음부터 다시 매겨야 한다.

## 평가 결과 초기화

결과 탭 → `평가 결과 초기화` → `clearEvaluations` (교수 비밀번호 필요)

- 범위: **현재 보고 있는 학년만** / **전체 학년**
- 학년 범위는 `assignedMap[sid].grade` 기준이다 = 그 학년 팀에 배정된 학생.
  다른 학년에서 데려온 학생도 함께 지워진다 (보드에 보이는 것과 일치)
- `withPasswords` 를 켜면 학생 비밀번호도 함께 지운다. 끄면 학생이 같은 비밀번호로 다시 평가할 수 있다
- **명단과 팀 배정은 건드리지 않는다.** 같은 팀 구성으로 평가를 다시 받을 수 있다
- 배정이 풀린 뒤에 제출된 평가는 학년으로 매칭되지 않으므로 '전체'로만 지워진다

### 개인별 초기화 — 두 가지를 구분할 것

같은 학생을 되돌리는 방법이 두 개 있고, 지우는 범위가 다르다.

| 위치 | 버튼 | 액션 | 지우는 것 |
|---|---|---|---|
| 결과 표 `제출` 열 | **`제출 초기화`** | `clearStudentEvaluation` | 점수 **+ 비밀번호** |
| 학생 상세 모달 | **`비밀번호만 초기화 (점수 유지)`** | `resetStudentPassword` | 비밀번호만 |

**왜 `제출 초기화` 가 비밀번호까지 지우는가** — 학생은 자기 비밀번호로 다시 들어와 언제든
점수를 고칠 수 있었다. 그러니 교수가 초기화를 누르는 상황은 그 학생을 **처음부터 다시**
시작하게 하려는 것이다. 비밀번호를 남겨두면 비밀번호를 잊은 학생은 초기화를 해줘도
여전히 들어오지 못한다.

- 버튼은 **지울 것이 있는 학생**에게만 나온다 (제출했거나 비밀번호를 만든 학생).
  둘 다 없으면 서버가 `'nothing to clear'` 로 거부한다
- 결과 탭 잠금을 풀 때 확인한 `resultsPassword` 를 재사용하므로 매번 다시 묻지 않는다
- 지운 뒤 `fetchResults` 로 점수를 다시 받아온다 (평균이 어긋나지 않게)

## 서버 액션

| 액션 | 비밀번호 | 비고 |
|---|---|---|
| `uploadRoster` | 교수 | 명단 교체 — 팀·평가·학생비번 전부 삭제 |

| `setEvalEnabled` | 교수 | 평가 개시/마감 |
| `setStudentPassword` | 학생(생성) | 최초 1회만 |
| `getMyEvaluation` | **학생** | 읽기 전용. 본인 점수만 |
| `submitEvaluation` | **학생** | 평가가 열려 있을 때만 |
| `getResults` | **교수** | 읽기 전용. 전체 점수 |
| `clearEvaluations` | 교수 | 학년별/전체 |
| `clearStudentEvaluation` | 교수 | 학생 한 명 초기화 — 점수 + 비밀번호 삭제 |
| `resetStudentPassword` | 교수 | 학생 비번 분실 대응 |
| `resetAll` / `changePassword` / `verifyPassword` | 교수 | |

`readOnly: true` 를 돌려주는 액션은 시트에 쓰지 않는다 (`getMyEvaluation`, `getResults`).

## 데이터 구조 (서버 시트에 저장되는 실제 state)

```js
{
  roster: [ { grade, section, studentId, name } ],   // grade = 명단상 원 소속
  teamsByGrade: {
    '1': { teamCount,                              // 반별 합계 (파생값)
           teamCountBySection: { a:10, b:10, c:10 },
           teams: [ { id:'t1', name:'1팀', title?, section:'a',
                      roles: { 기획:[], 아트:[], 개발:[] } } ] },
    '2': { teamCount, teams: [...], individual: [] }  // 2·3학년만 individual
  },
  assignedMap: { 학번: { grade, target, role } },     // grade = 배정된 팀의 학년
  evaluations: { 평가자학번: { 피평가자학번: 점수 } }, // ⚠️ 공개 안 됨
  studentAuth: { 학번: { salt, hash } },              // ⚠️ 공개 안 됨
  evalEnabled: false
}
```

`assignedMap` 은 **파생 데이터**다. `rebuildAssignedMap()` 으로 `teamsByGrade` 에서 다시 만들 수 있다.

## 서버 동기화 방식

- 모든 통신은 `callServer(action, payload, password, onDone)` 하나를 거친다
- `pollServer()` 가 5초마다 공개 상태를 가져와, JSON 문자열이 달라졌을 때만 `applyServerState()`
- 서버가 내려준 상태는 **항상 `normalizeState()` 를 통과시킨다** (`submittedIds`/`authedIds` 기본값 채우기, 옛 캐시의 `evaluations` 제거)
- `lastStateJson` 으로 불필요한 리렌더를 막고, `uiBusy()` 로 입력 중 리렌더를 막는다

**여러 명이 동시에 쓰는 앱이다.** 상태를 통째로 덮어쓰는 액션은 만들지 말 것.

## 명단 엑셀 파싱 규칙 (`parseWorkbook`)

까다로우니 고치기 전에 반드시 읽을 것.

- 워크북의 **모든 시트**를 순회한다
- 각 시트 **앞 5행 안에서** `학번` 과 `이름` 이 둘 다 있는 행을 헤더로 인식. 없으면 그 시트는 건너뜀
- 인식하는 열: `No` / `학번` / `이름` / `학적반`
- **시트 이름에서 학년·분반을 추출한다.** 패턴: `^\s*(\d+)\s*-\s*([A-Za-z가-힣0-9])` → 예: `2-A` 면 2학년 A반
- 유효 행 판정: `No` 가 숫자 + `학번` 이 8~10자리 숫자 + `이름` 이 비어있지 않음

즉 **시트 이름 규칙이 곧 학년 정보**다. 이 정규식을 건드리면 명단 업로드가 통째로 깨진다.

## 내보내기

- **팀 배정 내보내기** (`buildTeamExportRows`) — 열: 구분 / 반 / 팀명 / 역할 / 학번 / 이름 / 명단학년 / 학적반.
  다른 학년에서 데려온 학생을 표만 보고 구분할 수 있게 `명단학년` 을 넣는다
- **고급 · 현재 상태 내보내기** — `SEED_STATE` 코드 생성. **명단과 팀 구성만** 담는다.
  점수를 담으면 공개된 `index3.html` 에 전교생 점수가 박히는 셈이라 제외했다
  (그래서 `canonicalRatingPairs` / `encodeEvaluations` / `decodeEvaluations` 는 삭제됨)

## 백엔드 배포 (`apps-script/Code.gs`)

1. https://script.google.com 새 프로젝트에 파일 내용 붙여넣기
2. 배포 > 새 배포 > 웹 앱 / 실행 사용자: 나 / 액세스: 모든 사용자
3. 최초 1회 구글 계정 권한 승인 (교수만, 학생은 불필요)
4. 발급된 `.../exec` URL을 `index3.html` 의 `API_URL` 에 넣기

**코드를 고친 뒤에는 "배포 관리 > 편집 > 버전: 새 버전"으로 재배포해야 반영된다.** URL은 유지된다.
git push만으로는 절대 반영되지 않는다.

> ⚠️ 클라이언트만 배포하고 서버를 재배포하지 않으면, 옛 서버가 여전히 점수를 공개로 내려준다.
> `index3.html` 과 `Code.gs` 는 **항상 같이** 올려야 한다.

## 수정할 때 주의

- `Code.gs` 와 `Timetable.gs` 는 **완전히 별개 프로젝트**다. 공통화하지 말 것.
- `Code.gs` 에 `DEFAULT_PASSWORD = '1004'` 가 평문으로 있고 저장소는 공개 상태다.
- 실제 수업에서 학생들이 동시에 접속해 쓰는 시스템이다. 배포 전 반드시 검증할 것.
- 오프라인 폴백에서도 비밀번호 확인을 건너뛰지 말 것. `fetchResults()` 는 서버에 닿지 못하면
  `checkPassword()` 로 로컬 확인을 하고, 실패하면 잠금을 열지 않는다.
